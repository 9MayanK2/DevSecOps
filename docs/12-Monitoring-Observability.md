# 1. Introduction

Building secure software is only one part of operating a modern platform. Once applications are deployed, engineering teams must continuously observe infrastructure, applications, and Kubernetes workloads to ensure reliability and performance.

SentinelOps integrates a complete monitoring stack based on **Prometheus**, **Grafana**, and **Alertmanager** to provide real-time visibility into the Kubernetes environment.

The monitoring platform helps teams answer questions such as:

- Is the application healthy?
- Are Kubernetes Pods running correctly?
- Are nodes running out of CPU or memory?
- Are deployments failing?
- Are alerts being triggered?

---

# 2. Why Monitoring?

Without monitoring, failures often remain undetected until users report them.

Monitoring enables:

- Infrastructure health visibility
- Application health monitoring
- Capacity planning
- Incident detection
- Performance analysis
- Historical trend analysis
- Alert generation

# 6. Prometheus Architecture

Prometheus is responsible for collecting and storing metrics.

Current responsibilities:

- Scrape Kubernetes metrics
- Monitor Nodes
- Monitor Pods
- Monitor Services
- Store time-series data

Prometheus continuously polls configured targets at fixed intervals.

Typical metrics include:

- CPU utilization
- Memory utilization
- Disk usage
- Network traffic
- Pod status
- Deployment health

---

## Prometheus Workflow

```text
Target Discovery

↓

Scrape Metrics

↓

Store Time Series

↓

Evaluate Rules

↓

Generate Alerts

↓

Grafana / Alertmanager
```

# 7. Grafana Dashboard

Grafana provides visual dashboards for operational monitoring.

Current implementation includes:

- Kubernetes Cluster Dashboard

- Pod Resource Dashboard

Dashboard capabilities:

- CPU utilization
- Memory utilization
- Node health
- Pod health
- Deployment status
- Namespace statistics

Grafana retrieves all metrics directly from Prometheus.

# 8. Alertmanager

Alertmanager processes alerts generated by Prometheus.

Responsibilities include:

- Alert grouping
- Alert deduplication
- Alert routing
- Notification management

Example alerts:

- Node unavailable
- High CPU usage
- High memory usage
- Pod crash
- Deployment failure
- Persistent volume issues

---

# 9. Node Exporter

Node Exporter collects operating system metrics from Kubernetes worker nodes.

Example metrics:

- CPU usage
- Memory usage
- Filesystem usage
- Network traffic
- Load average
- Disk I/O

These metrics help operators understand the health of the underlying infrastructure.

---

# 10. kube-state-metrics

kube-state-metrics exposes the state of Kubernetes resources.

Examples:

- Deployments
- ReplicaSets
- Pods
- Nodes
- StatefulSets
- Services
- PersistentVolumeClaims

Unlike Node Exporter, which monitors operating system metrics, kube-state-metrics provides visibility into Kubernetes objects.

---

# 11. Storage Architecture

Prometheus stores time-series metrics using persistent storage.

SentinelOps currently uses:

- Amazon EBS
- EBS CSI Driver
- gp3 StorageClass

Persistent volumes are configured for:

- Prometheus
- Grafana
- Alertmanager

This ensures monitoring data remains available after Pod restarts.

# 15. Summary

SentinelOps provides a cloud-native observability platform built on Prometheus, Grafana, Alertmanager, Node Exporter, and kube-state-metrics.

Together, these components deliver real-time visibility into infrastructure health, Kubernetes workloads, and application performance, forming the operational foundation for reliable and secure software delivery.

The monitoring stack is designed to evolve into a comprehensive observability platform by incorporating runtime security, centralized logging, distributed tracing, and advanced security analytics.
